Module 1 · Architecture, layering & performance · Lectures 1–4
Lecture 1 · Internet foundations

What is a computer network?

A computer network is a set of devices connected by communication links and rules (protocols) that let applications exchange data. The Internet is not one giant cable or one company’s network: it is a network of networks that interconnects homes, universities, companies, and Internet service providers.

One common network-layer service

Networks underneath may use different technologies, but IP supplies a common addressing and packet-forwarding layer across them. IP addresses identify interfaces in this shared logical space.

Best effort means no promise

IP (Layer 3) tries to forward a datagram, but by itself does not promise delivery, order, a delay bound, or no duplicates. Packets may be lost, delayed, reordered, or duplicated. Higher layers can add guarantees where needed.

Networks exist for applications

Web browsing, file transfer, voice calls, video, games, and messaging have different needs. Some prioritize throughput; interactive voice prioritizes latency and low jitter; a reliable download cares that every byte arrives.

Requirements worth naming in an answer

RequirementMeaningExample concern
Connectivity / reachabilityCan a source communicate with the intended destination?Can packets cross multiple networks to reach a server?
MultiplexingCan multiple users, applications, or flows share resources and still be distinguished?Ports distinguish processes; statistical sharing uses capacity when flows need it.
Congestion handlingWhat happens when offered traffic exceeds a link or router’s capacity?Queues grow, delay rises, buffers may overflow and drop packets.
PerformanceHow fast, how quickly, and how consistently does data arrive?Throughput, latency, and jitter.

Exam-ready sentence: “The Internet is a network of interconnected networks using IP as a common Layer-3 addressing and forwarding service. IP is best effort, so delivery and timing guarantees must come from another mechanism if the application needs them.”

Lecture 2 · Abstraction, layers & sockets

Layers let each part solve one kind of problem

Layering is an abstraction: an application uses a service without needing to know every detail of the physical link. A protocol defines the messages and rules peers at the same layer follow. Each layer uses the layer below and provides a service to the layer above.

At the receiver, decapsulation removes the headers in reverse order. A router usually reads the IP header and forwards the packet; it does not need to understand the HTTP request.

Socket = application endpoint

A socket API lets a program communicate through the network stack. A TCP server typically performs passive open with socket → bind → listen → accept; a client actively connects with socket → connect.

Ports = process demultiplexing

An IP address gets a packet to a host interface; a transport port helps the OS deliver it to the correct process. A connection is commonly identified by source/destination IP addresses and ports plus the transport protocol.

Socket programming: the program's view

Server: socket → setsockopt → bind → listen → accept
Client: socket → connect
Both:   read/write bytes → close

socket() returns a file descriptor (a small integer handle). bind() associates the server with a local address/port; listen() prepares a TCP listening socket; accept() returns a new connected descriptor for one client. The client calls connect(). After connecting, each side uses read() and write(); either can transfer fewer bytes than requested, so a real program loops and tracks how many bytes remain. close() releases the descriptor. This is the same lifecycle used by the Lab 7 TCP file-transfer programs.

Lecture 3 · Network architecture & switching

How do networks grow and share resources?

A useful design must serve multiple stakeholders: users and application builders want useful connectivity and performance; network operators need a system they can deploy, manage, and scale. The lecture frames network design around scalable connectivity, cost-effective sharing, and support for common services.

Direct link

A physical or logical link connects two participants. A direct link is simple, but connecting every pair in a large network requires many links.

Switching

A switch connects multiple links and forwards data toward an output. It lets many endpoints communicate without a direct cable between every pair.

Store-and-forward

A switch receives a packet/frame (or enough of it to make a forwarding decision) and forwards it over the next link. The packet can wait in a queue when the output is busy.

Addresses answer “who?”; routing answers “which way?”

An address identifies a reachable endpoint/interface. A route or forwarding decision selects a next hop toward a destination. These are related but different jobs: the address names the destination; the route helps move the packet there.

Delivery styleMeaningExample
UnicastOne sender to one destination.A client requests one web server.
BroadcastOne sender to all relevant nodes in a local broadcast domain.An ARP request on an IPv4 LAN.
MulticastOne sender to members of a group; the network can replicate where paths branch.Receivers join a group instead of each getting a separate unicast stream.

Sharing capacity: circuit and packet switching

Circuit switching reserves a path/resource for a session, which can make capacity predictable but may leave a reservation unused. Packet switching shares link capacity among bursts of traffic; this statistical multiplexing is efficient for bursty computer data, but can create queues and congestion.

Congestion chain: traffic arrives faster than an outgoing link can transmit → queue builds → latency increases → finite buffer fills → packets are dropped. A network cannot create bandwidth by buffering; it only delays the overload for a while.

Lecture 4 · Performance & channels

Bandwidth is not latency—and neither is throughput

Bandwidth / link rate

The transmission capacity of a link, usually bits per second. It determines how quickly bits can be put onto the link.

Latency / delay

Time from sending to receiving. It includes processing, queueing, transmission, and propagation delays.

Throughput

The achieved rate of useful data transfer. It is limited by the bottleneck and can be less than the link’s nominal bandwidth.

Jitter

Variation in packet delay. A steady stream can play smoothly; variable delay may require a playback buffer and can make real-time media choppy.

Two delays to never confuse

Transmission delay is the time to put a packet of L bits onto a link with rate R bits/s: dtrans = L / R. Propagation delay is the time for a signal to travel a distance d at propagation speed s: dprop = d / s. Increasing the link rate reduces transmission time, not the physical propagation time.

A path’s delay can also include processing at devices and time waiting in queues. For several store-and-forward links, each hop contributes its relevant transmission and propagation delays; queueing varies with load.

Delay × bandwidth product: bits “in flight”

Multiply a link rate by a round-trip time to estimate how much data can be in flight before an acknowledgment returns. For a one-way link, use the relevant one-way delay; for the Stop-and-Wait formula below, use RTT.

BDP (bits) = rate (bits/s) × delay (s)

Example: at 20 Mb/s and 50 ms one-way delay, the one-way BDP is 20,000,000 × 0.05 = 1,000,000 bits = 125,000 bytes. Convert milliseconds to seconds and bits to bytes carefully.

Which application is constrained by which metric?

  • A small request/reply can be latency-bound: waiting for a round trip dominates sending the few bytes.
  • A large file can be bandwidth-bound once a pipeline is full.
  • A live stream may need sustained throughput, bounded startup time, and low jitter.

Lecture 5 · UDP, ports & Stop-and-Wait

Transport connects processes, not just computers

IP moves datagrams between hosts/interfaces. The transport layer delivers data between application processes using ports. It may add reliability, flow control, or congestion control—but UDP deliberately keeps its service small.

PropertyUDPTCP
ServiceConnectionless datagramsConnection-oriented byte stream
Ports / multiplexingYesYes
Built-in reliable ordered deliveryNoYes, using sequence numbers, acknowledgments, retransmission, and windows
Message boundariesEach UDP datagram is a messageTCP exposes a byte stream, not application message boundaries
Typical trade-offLess transport machinery; application may accept loss or implement what it needsMore guarantees and state; application waits for a reliable ordered stream

UDP’s header includes source and destination ports, length, and checksum. The checksum can detect corruption; it does not retransmit data. A pseudoheader in the checksum calculation helps detect delivery to the wrong IP endpoints. UDP’s checksum is optional in IPv4 (but not in IPv6).

ARQ: use acknowledgments and timeouts to recover

Automatic Repeat reQuest (ARQ) uses acknowledgments and retransmission. If a data frame or its ACK is lost, the sender’s timer expires and it resends. Sequence numbers let the receiver recognize a duplicate when the original arrived but its ACK was lost.

Stop-and-Wait allows only one unacknowledged packet at a time. It is simple but wastes a high-delay, high-rate link while waiting for the ACK.

U ≈ Tdata / (RTT + Tdata) = 1 / (1 + RTT / Tdata)

Here Tdata = L/R. The approximation assumes ACK transmission and processing are small. If RTT = 2Tprop and ACK time is ignored, the same result is 1/(1 + 2a), where a = Tprop/Tdata. A very small packet on a long-RTT path has low utilization.

Lecture 6 · Sliding windows

Keep the path busy with a window

A sliding-window protocol allows multiple packets to be outstanding. The sender remembers sent-but-not-yet-acknowledged data; as ACKs arrive, the send window advances. The receiver tracks what it can accept. This pipeline can fill a path’s bandwidth-delay product rather than waiting after every packet.

Approx. utilization = min(1, W × Tdata / (RTT + Tdata))

W is the number of packets the sender can keep in flight. To approach full utilization, W needs to be large enough to cover the round-trip waiting time—roughly the bandwidth-delay product in packets.

ProtocolReceiver behaviorWhat happens after a loss?
Go-Back-N (GBN)Typically accepts in-order frames and cumulatively ACKs the next expected sequence number.Sender retransmits the missing frame and all later outstanding frames that may have been discarded.
Selective Repeat (SR)Can buffer correctly received out-of-order frames and acknowledge them individually.Retransmit only missing/unacknowledged frames. More buffering and state are required.

Why sequence-number space limits the window

Sequence numbers wrap around. If an old frame and a new frame have the same number while both could be confused, the receiver cannot tell which is which. For an m-bit sequence number space of size N = 2m, Selective Repeat needs the window no larger than half the space (W ≤ N/2) so old and new ranges do not overlap ambiguously. Go-Back-N’s sender window has its own common bound W ≤ N − 1; follow the protocol variant and assumptions stated in the question.

TCP applies sliding-window ideas to bytes: sequence numbers identify byte positions, ACKs are cumulative, and flow/congestion windows bound what can be in flight.

Lecture 7 · TCP connections & control

TCP turns a best-effort network into a reliable byte stream

TCP keeps per-connection state at each endpoint. It numbers bytes, acknowledges received data, retransmits missing data, delivers bytes in order, and uses windows to avoid overrunning the receiver or the network.

TCP segment: a transport header plus data

Important fields include source/destination ports, sequence number, acknowledgment number, control flags (such as SYN, ACK, FIN, RST), advertised receive window, checksum, and payload. The IP packet carries the TCP segment across networks.

Three-way handshake

Client
SYN, seq = x
→
Server
SYN + ACK, seq = y, ack = x+1
←
Client
ACK, ack = y+1

The SYNs establish shared connection state and exchange each side’s initial sequence number. The third ACK confirms that both endpoints received the opening information. SYN consumes one sequence-number position.

Closing and reset

Each direction can close independently. A FIN says “I have no more data to send”; the peer ACKs it, and later sends its own FIN when ready. This is a symmetric close (often four control segments, with ACKs sometimes combined). RST aborts a connection abruptly rather than performing an orderly close.

Flow control vs. congestion control

Receiver protection · rwnd

The receiver advertises how much buffer space it can accept. This prevents a fast sender from overflowing the receiver’s memory.

Network protection · cwnd

The sender limits data in flight based on the network’s estimated capacity. Congestion control reacts to network signals/loss instead of flooding congested paths.

Send window ≤ min(rwnd, cwnd)

Adaptive retransmission timeout: the sender estimates round-trip time from observations and sets a retransmission timeout (RTO) with safety margin. A fixed timer could be too short on a slow path or wasteful on a fast one. After a timeout, TCP retransmits; congestion response also reduces sending pressure.

Lost-packet trace: a segment is missing → later data may reveal a gap through duplicate cumulative ACKs → sender can retransmit the missing bytes (fast retransmit) or wait for timeout → the receiver restores an in-order byte stream → congestion control reduces the sending rate when loss signals congestion.

Module 3 · IP, routing & internetworking · Lecture 9
Lecture 9 · Addressing, NAT, IPv6 & multicast

IP addresses have a network prefix and an interface part

An IPv4 address is 32 bits. CIDR notation 192.0.2.37/24 says the first 24 bits are the network prefix; the remaining 8 bits identify an address within that subnet. A subnet mask has 1s for prefix bits and 0s for host bits.

Classful addressing used fixed /8, /16, and /24 boundaries. CIDR replaced those rigid classes with variable-length prefixes, allowing more efficient allocation and route aggregation.

Subnet arithmetic example

For 192.0.2.37/24, mask = 255.255.255.0, network = 192.0.2.0, and 8 host bits give 28 = 256 total address patterns. In a conventional IPv4 subnet, the all-zero host address is the network identifier and the all-one host address is broadcast, leaving 254 ordinary host addresses. Small special prefixes such as /31 and /32 have different usage rules.

Special ranges, NAT, IPv6

  • Private IPv4 ranges are intended for internal networks and are not globally routed as public destinations. NAT commonly rewrites private source address/port mappings to a public address and maps returning traffic back.
  • NAT conserves public IPv4 addresses but changes end-to-end addressing behavior; it is not the same thing as a firewall.
  • IPv6 uses 128-bit addresses, has a much larger space, and writes hexadecimal groups separated by colons. Leading zeros may be omitted and one run of zero groups may be compressed with ::.

Multicast: send once to a group

A sender targets a multicast group address. Receivers join the group; for IPv4, IGMP communicates local membership. Multicast routing builds distribution paths and replicates packets where paths branch, rather than asking the sender to send a separate unicast copy to every receiver.

Forwarding vs. routing: routing computes/maintains paths; forwarding is the per-packet action of selecting an output/next hop. State this difference when a question asks how a router moves traffic.

Module 4 · Switches, Ethernet & Wi-Fi · Lectures 10–11
Lecture 10 · Switch learning & loop prevention

A Layer-2 switch learns by watching source addresses

A switch keeps a forwarding table mapping MAC address → port. When a frame arrives, it learns the source MAC on the incoming port. If the destination is known, it forwards only to the matching port (unless that is already the incoming port). If unknown, or if the frame is broadcast, it floods out other eligible ports.

  1. Frame arrives on port 2, source MAC A, destination MAC B.
  2. Learn “A is reachable via port 2” (refreshing a previous entry if necessary).
  3. Look up B. If B is known on port 4, send there; if unknown, flood other ports.
  4. A reply from B teaches the switch which port reaches B. Later A↔B frames can be unicast through the learned ports.

Why a loop is dangerous

Redundant links are useful for resilience, but a Layer-2 loop plus broadcast/unknown-destination flooding can circulate frames indefinitely and multiply traffic. The Spanning Tree Protocol (STP) elects a root bridge and blocks selected redundant links to form a loop-free logical tree. A blocked link can be activated if the active topology fails.

Lecture 11 · Ethernet, MACs, Wi-Fi & VLANs

Frames move across one link; routers move between networks

Ethernet frame

An Ethernet frame includes a preamble for synchronization, destination and source MAC addresses, a Type field, payload, and a frame-check sequence (CRC) for error detection. Ethernet detects a damaged frame; it does not itself guarantee that the frame is retransmitted end-to-end. Classic Ethernet payload MTU is commonly 1500 bytes.

MAC addresses and learning

A MAC address is a 48-bit link-layer identifier, commonly shown as six hexadecimal byte pairs such as 00:1A:2B:3C:4D:5E. Switches learn source MACs and associate them with ports. MAC addressing is for delivery on a local Layer-2 link; IP addresses provide logical addressing across routed networks.

Wi-Fi: access points and CSMA/CA

In infrastructure mode, stations (phones/laptops) associate with an access point (AP); the AP bridges wireless stations into the LAN. Stations communicate through the AP, rather than directly with each other. An SSID names the wireless network; WPA2/WPA3 provide authentication and link protection.

CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance): Wi-Fi stations listen before transmitting, defer when the medium is busy, and use randomized backoff to reduce the chance of colliding with another station. A receiver’s ACK confirms a frame arrived; missing ACK can trigger a retry. Wireless transmitters generally cannot reliably listen for a collision while sending, so Wi-Fi tries to avoid collisions rather than detect them as classic shared-wire Ethernet did. Hidden stations and radio interference make “listen first” imperfect; optional RTS/CTS can help reserve airtime in some situations.

CSMA/CA is supplementary context requested for this portal. The supplied Lecture 11 slides cover Wi-Fi infrastructure, APs, association, and LAN integration (PDF pp. 837–845), but do not present a dedicated CSMA/CA mechanism lesson.

LAN, broadcast domain, and VLAN

A LAN is a local administrative and Layer-2 domain. Switches flood broadcasts within a broadcast domain; a router separates Layer-2 broadcast domains. A VLAN partitions one physical switching infrastructure into multiple logical LANs. Devices in different VLANs need Layer-3 routing to communicate.

On a trunk between switches, IEEE 802.1Q tags identify the VLAN. The VLAN ID is 12 bits; 4094 VLAN IDs are usable (0 and 4095 are reserved). Switch learning is kept per VLAN, so a MAC-to-port entry belongs to a VLAN context.

Lecture 12 · DHCP, ARP, gateway, DNS & IPv6

What happens when a new device joins a network?

DHCP: lease configuration automatically

DHCP supplies a host with an address lease and configuration such as subnet mask, default gateway, and DNS server. A new IPv4 host begins without a usable address and uses broadcast communication to discover a server. Remember DORA:

Discover
client broadcasts
→
Offer
server proposes config
→
Request
client asks for offer
→
Ack
server grants lease

DHCP uses UDP ports 68 (client) and 67 (server). Relay agents let a server on another network serve clients whose initial broadcast cannot cross a router. Leases expire and can be renewed.

ARP: find a local IPv4 next-hop MAC

To send an IPv4 packet over Ethernet, a host needs a destination MAC address for the local link. If the target IP is on the same subnet, ARP resolves that host’s IP to its MAC. If the target is off-subnet, the host resolves the default gateway’s IP to the gateway’s MAC—not the remote server’s MAC. ARP request is broadcast; the matching device replies with its MAC, usually by unicast. Results are cached temporarily.

Gateway: same IP destination, hop-by-hop link addresses

For an off-subnet destination, the host sends the frame to its default router. The IP destination remains the remote host as the packet crosses routers; the link-layer source/destination MAC addresses are rewritten for each hop. A router removes the incoming frame, routes the IP packet, and wraps it in a new outgoing-link frame. IPv6 uses Neighbor Discovery Protocol (NDP), not ARP.

DNS: translate a name into an address

DNS is a distributed hierarchy of names, zones, and servers. A resolver can use cached answers; otherwise it follows referrals (root → top-level domain → authoritative server) to find a record such as an A (IPv4) or AAAA (IPv6) address. DNS answers have TTLs and may be cached.

Put the services together

  2. Local delivery decision: the client compares the destination IP with its own prefix. If remote, it sends to the configured default gateway.

Lecture 13 · Organize the full story

Connect the topics into one mental model

The Lecture 13 slides are a revision tour, not a new protocol unit. Their summary groups the course into foundations and performance, transport/reliability, IP, and local networks. The following progression is a useful way to structure an open-ended answer:

  1. Application need: identify communication endpoints and whether the app needs throughput, low delay/jitter, or reliable delivery.
  2. Transport: choose UDP’s minimal datagram service or TCP’s reliable connection-oriented byte stream. Name the ports/processes.
  3. Network: give the destination IP, determine local vs remote prefix, and select direct host or default gateway.
  4. Link: deliver a frame to the next-hop MAC using Ethernet or Wi-Fi. Switches learn MAC-to-port mappings; STP prevents loops.
  5. Services: DHCP supplies configuration; DNS resolves names; ARP/NDP resolves a local next-hop link address.
  6. Performance and failures: identify bottlenecks, queueing, packet loss, ACK/retransmission behavior, and receiver/network protections.

Mechanisms in one breath

DHCP · DORA

Discover → Offer → Request → Ack. Uses UDP 67/68; configures address, mask, gateway, DNS lease.

ARP

Broadcast “who has this local IPv4 address?” → owner replies with MAC → cache mapping.

DNS

Check cache → ask recursive resolver → follow root/TLD/authoritative referrals as needed → cache answer according to TTL.

TCP open

Client SYN → server SYN+ACK → client ACK. Exchange initial sequence numbers; connection state is established.

TCP close

Each direction FINs independently; peer ACKs. RST is an abrupt abort.

Switch learning

Learn source MAC on ingress port → look up destination → known unicast, or flood unknown/broadcast in the VLAN.

Spanning tree

Elect root → choose loop-free forwarding tree → block redundant ports → recover topology when active path fails.

CSMA/CA

Listen → defer if busy → random backoff → transmit → wait for ACK; retry if no ACK. Avoid, rather than detect, wireless collisions.

Open-answer readiness · Practice explaining out loud

Exam scenarios with answer-building guides

Before revealing each guide, try to write a short answer using the terms from the course. Strong answers state the mechanism, walk through events in order, and explain why.

Scenario 1 · Stop-and-Wait packet or ACK loss

Prompt: Sender transmits frame 0. The receiver gets it and sends an ACK, but the ACK is lost. Explain what happens next and why the application does not receive duplicate data.

Answer guide: Sender timer expires because no ACK arrived; sender retransmits frame 0. Receiver recognizes the sequence number as a duplicate, discards duplicate payload, and sends the ACK again. Sender then advances to the next sequence number. Name timeout, sequence number, duplicate detection, and re-ACK.

Scenario 2 · Go-Back-N loss in a window

Prompt: Sender sends frames 0, 1, 2, 3. Frame 1 is lost; later frames reach a receiver that only accepts in-order data. Describe ACKs and retransmission.

Answer guide: Receiver accepts 0 and cumulatively ACKs the next expected frame (1). It discards out-of-order 2 and 3 and repeats an ACK indicating 1 is still missing. After timeout/fast-loss inference, sender retransmits 1 and outstanding later frames (1, 2, 3). Contrast with Selective Repeat, which can buffer later frames and retransmit only missing data.

Scenario 3 · TCP receiver is slow, network is healthy

Prompt: The application at the receiver is not reading data quickly. Which TCP mechanism should limit the sender, and what is it protecting?

Answer guide: Receiver advertises a smaller receive window (rwnd), limiting outstanding bytes and protecting its buffer. Do not call this congestion control; cwnd estimates a network-safe sending amount. Sender is constrained by min(rwnd, cwnd).

Scenario 4 · Remote web server on another subnet

Prompt: A laptop resolves a server’s IP, but it is outside the laptop’s subnet. Which MAC address goes in the first Ethernet frame? What changes at the router?

Answer guide: The frame’s destination MAC is the local default gateway’s MAC, obtained via ARP if not cached. IP destination remains the remote server’s IP. Router removes the incoming link frame and sends a new frame on the next link, with new source/destination MACs. The IP source/destination generally remain end-host addresses (apart from mechanisms such as NAT).

Scenario 5 · Two VLANs share a switch

Prompt: Hosts on VLAN 10 and VLAN 20 use the same physical switch. Can an Ethernet broadcast from VLAN 10 reach VLAN 20? Explain.

Answer guide: No. VLANs form separate logical Layer-2 broadcast domains. Switch forwarding/flooding is VLAN-scoped; 802.1Q tags carry VLAN identity on trunks. Communication between VLANs needs Layer-3 routing.

Scenario 6 · A Wi-Fi station has data to send

Prompt: Explain how CSMA/CA reduces collisions and how the station knows a frame was received.

Answer guide: Station senses channel; if busy, defers. It waits a randomized backoff to reduce simultaneous starts, then transmits and waits for an ACK. No ACK implies likely loss/collision/interference and can trigger retry/backoff. A hidden station may not hear another transmitter; RTS/CTS can help reserve the medium.

Scenario 7 · Calculate a Stop-and-Wait utilization

Prompt: A 1000-byte frame goes over a 1 Mb/s link. RTT is 40 ms; ACK time is negligible. Estimate utilization.

Answer guide: Convert 1000 bytes to 8000 bits. Tdata = 8000 / 1,000,000 = 0.008 s = 8 ms. U = 8/(40+8) = 1/6 ≈ 0.167, or about 16.7%. State the assumption that ACK time is negligible.

Scenario 8 · DHCP, DNS, HTTP in a new network

Prompt: A host joins a LAN and then browses to a domain it has not visited. Explain the main protocols and order.

Answer guide: DHCP DORA assigns an address, subnet mask, gateway, DNS server. DNS resolver obtains the domain’s IP (unless cached). Host compares prefix; if remote, it ARPs for gateway MAC. TCP handshake establishes process-to-process connection; HTTP GET is carried as TCP bytes inside IP packets/frames. Response follows reverse path; each router rebuilds link-layer frames.

Answer skeleton

1. Name the layer/protocol.
2. State the problem it solves.
3. Trace events in order (who sends what to whom?).
4. Say what can be lost/changed/learned at each step.
5. State the outcome and any assumption.
